# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`Chat` is a SwiftUI iOS chat app (iOS 26.5+, Swift 5 toolchain) built with Xcode. No SPM/CocoaPods dependencies — pure first-party code plus a local `Resources` framework target for generated assets.

## Build & Run

There is no CLI test suite or lint config in this repo. Use Xcode or `xcodebuild`:

```bash
# Build the app target
xcodebuild -project Chat.xcodeproj -scheme Chat -destination 'platform=iOS Simulator,name=iPhone 17' build

# List available schemes/targets
xcodebuild -project Chat.xcodeproj -list
```

Open `Chat.xcodeproj` in Xcode for iterating with previews (most views have `#Preview` blocks) — this is the fastest feedback loop for SwiftUI work in this repo.

### Regenerating asset symbols

`Resources/Generated/Assets.swift` is generated by SwiftGen from `Resources/swiftgen.yml`, which reads `Resources/Assets/{Images,Icons,Colors}.xcassets`. Run `swiftgen` from the `Resources/` directory after adding/renaming assets; do not hand-edit `Generated/Assets.swift`.

## Architecture

Two Xcode targets:
- **Chat** (app) — all feature code, under `Chat/`.
- **Resources** (framework) — asset catalogs + SwiftGen-generated accessors, under `Resources/`. Bundle access goes through `ResourcesBundle.bundle` (`Resources/Resources.swift`).

### Module layout (`Chat/`)

- `App/` — entry point (`ChatApp`), root `MainTabView`, and the `MainTab` enum driving the two-tab UI (Chats, Contacts).
- `Authentication/` — auth/login/signup/profile-setup screens (`AuthView`, `LoginView`, `SignUpView`, `SetupProfileView`). Currently UI-only, no backing store/service yet.
- `ChatsModule/` — chat list feature: `ChatListView` (screen) + `ChatListStore` (state) + `Views/` for row/section subcomponents (`WaitingChatRow`, `ActiveChatRow`, `ChatSectionHeader`).
- `ContactsModule/` — contacts list feature (`ContactListView`); currently a stub with no store.
- `Models/Chats/`, `Models/Contacts/` — plain data models (e.g. `ChatListModel`, `ChatListState`, `ContactsListModel`), each `Identifiable, Hashable, Sendable`, with static `.mock` data used for previews and the current mock-driven UI.
- `CommonElements/` — shared, reusable view building blocks used across Authentication/Chats/Contacts (buttons, form rows, layout wrappers, profile photo picker).
- `DesignSystem/` — `Layout` (all spacing/size constants, namespaced by feature: `AuthFlow`, `Chats`, `Contacts`, etc.) and `Typography` (all `Font` definitions). New UI code should pull spacing/fonts from these enums rather than hardcoding values.
- `Extensions/` — small foundation/string extensions (e.g. `String.firstWord`).
- `Resources/Localizable.xcstrings` — String Catalog for localized strings; views reference these via `LocalizedStringResource`/`.someKey` static members, not raw string literals.

### State management pattern

Feature state uses the `@Observable` macro (not `ObservableObject`), scoped per-module as a `Store` class (see `ChatListStore`: `@MainActor @Observable final class`). Stores own the raw mock data plus derived/filtered collections (e.g. `waitingChats`/`activeChats`) recomputed via `didSet` observers rather than computed properties, to avoid recomputation on every view body evaluation. Screens hold their store via `@State private var store = ...`.

### Conventions

- Models are `nonisolated struct ... : Identifiable, Hashable, Sendable` with a default `UUID()` id, plus a static `.mock` array for previews/placeholder data — no networking/persistence layer exists yet.
- Avoid `!`, `as!`, and implicitly unwrapped optionals (per global Swift/SwiftUI guidance in `~/.claude/CLAUDE.md`, which also governs concurrency, architecture, and API-recency conventions for this repo).
- Every screen-level view includes an Xcode `#Preview`.
